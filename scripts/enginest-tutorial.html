Chapter 1

Tools you need to install

Before we write any code, we need to install the tools that make this whole workflow possible. Think of these as your workshop setup. Each tool has a specific job, and once they're installed, you never have to think about them again. Take your time with this chapter, because getting the setup right prevents 90% of the frustrating errors later.

1. Node.js — runs JavaScript on your computer

Node.js is a runtime that lets your computer execute JavaScript outside of a browser. We need it because Next.js (the framework we'll use) is built on top of Node. Without Node, your computer cannot run the development server that shows your site as you build it. Install the LTS (Long Term Support) version, which is the most stable. Verify it works by opening a terminal and running node -v. You should see something like v20.11.0. If you see "command not found", restart your terminal or reinstall.

2. VS Code — your code editor

VS Code is a free code editor from Microsoft. It is the de facto standard for web development because it has great syntax highlighting, integrated terminal, and a massive extension ecosystem. Download it from code.visualstudio.com. Once installed, open it and press Ctrl + ` (backtick) to open the integrated terminal. You'll use this terminal for every command in this guide. Install the "ES7+ React/Redux/React-Native snippets" extension for faster React coding.

3. Git — version control for your code

Git is a version control system. It takes snapshots of your code at moments in time, so you can always go back if something breaks. Without Git, every change is permanent and irreversible. With Git, you can experiment freely. On Mac, Git is installed automatically when you install Xcode Command Line Tools (xcode-select --install). On Windows, download Git from git-scm.com. Verify with git --version.

4. A GitHub account — to save your code online

GitHub is a website that hosts Git repositories in the cloud. When you push your code to GitHub, two things happen: (1) your code is safely backed up, and (2) Vercel can automatically pull your code and deploy it every time you make a change. Sign up at github.com (free). Create a new empty repository called enginest. Do not add a README or .gitignore yet, we'll do that locally.

5. A Vercel account — to publish your site online

Vercel is a hosting platform built by the same team that makes Next.js. It is by far the easiest way to deploy a Next.js app: connect your GitHub repo, click Deploy, and you get a live URL on a global CDN in under 2 minutes. Sign up at vercel.com using your GitHub account (this links them together so deploys happen automatically).

6. An AI assistant — to write code with you

This is the most important tool. You'll use an AI assistant (like Claude, ChatGPT, or any coding-focused AI) to write the actual code. Your job is to describe what you want in plain English, and the AI generates the React components, CSS, and configuration. The rest of this guide is essentially a playbook for prompting the AI effectively. Pick whichever assistant you have access to. The exact prompts in this guide work across all of them.

Heads up: If you're on Windows, use Git Bash (installed with Git) instead of Command Prompt. All the commands in this guide are written for a Unix-style shell, and Git Bash gives you that on Windows.
Chapter 2

Create the Next.js project

Now we create the actual project. Next.js has an official scaffolding tool that asks you a few questions and sets up a complete project with sensible defaults. Run it from the folder where you want your project to live. The whole process takes about 90 seconds.

1
Open your terminal

Navigate to the folder where you keep your projects. For example: cd ~/projects. Create the folder if it doesn't exist: mkdir ~/projects && cd ~/projects.

2
Run create-next-app

Type this command and press Enter. Replace enginest with whatever you want to name your project. The installer will ask you a series of yes/no questions, listed below.

terminal
npx create-next-app@latest enginest

Answer each prompt as follows. These choices matter, so do not skip them:

  • Would you like to use TypeScript? — Yes. TypeScript catches bugs before they reach production by checking types at compile time.
  • Would you like to use ESLint? — Yes. ESLint flags common mistakes like unused variables or missing dependencies in React hooks.
  • Would you like to use Tailwind CSS? — Yes. Tailwind is a utility-first CSS framework that makes styling 5x faster than writing custom CSS.
  • Would you like your code inside a `src/` directory? — Yes. Keeps your project root clean.
  • Would you like to use App Router? — Yes. App Router is the modern Next.js routing system with nested layouts.
  • Would you like to use Turbopack for next dev? — No. Turbopack is fast but still in beta for some use cases; stick with webpack for stability.
  • Would you like to customize the import alias? — No. The default @/* alias is perfect.
3
Start the dev server

Once the installer finishes, navigate into your project and start the development server.

terminal
cd enginest npm run dev

Open your browser to http://localhost:3000. You should see the default Next.js starter page. Leave this terminal running in the background, every code change you save will hot-reload the browser automatically.

Pro tip: Open a second terminal tab for Git commands. You want one terminal always running npm run dev and another for everything else.
Chapter 3

Initialize Git and push to GitHub

Now we wire up version control. This is non-negotiable. Every change you make from here on out should be committed to Git, so you can roll back if an AI-generated change breaks something. Treat commits like save points in a video game.

1
Initialize the Git repository

This creates a hidden .git folder in your project that starts tracking file changes. Run this inside your project folder.

terminal
git init

create-next-app already created a .gitignore file for you, which tells Git to ignore node_modules, .next, and other generated folders. This is important because node_modules contains thousands of files and would bloat your repo. The .gitignore ensures only your source code gets committed.

2
Make your first commit

Staging means "I want to include these changes in the next commit". The dot means "everything". Then commit with a message.

terminal
git add . git commit -m "Initial commit: Next.js project scaffold"
3
Connect to GitHub

Go to github.com, create a new empty repository called enginest. Do NOT initialize with README. Copy the URL GitHub gives you (looks like https://github.com/yourname/enginest.git). Back in your terminal:

terminal
git remote add origin https://github.com/YOURNAME/enginest.git git branch -M main git push -u origin main

The -u origin main flag sets the default upstream, so future pushes can be done with just git push. Refresh your GitHub repo page, you should see all your project files there now.

Chapter 5

The Prompting Playbook

This is the most important chapter in the entire guide. The difference between a frustrating AI experience and a productive one is 100% in how you write your prompts. The good news: there is a formula. Every great prompt has the same five ingredients. Master this formula and you can build any website.

Anatomy of a great prompt

A great prompt contains five ingredients, in this order:

  • Subject: What you're building. Be specific. "Hero section" is good. "A nice landing area" is bad.
  • Colors: Exact hex codes. "#0F1B3D dark navy" is good. "Dark, professional" is bad. AI cannot guess your brand palette.
  • Layout intent: Centered? Two-column? Sticky sidebar? Tell the AI where things go spatially.
  • Interaction notes: Hover states, click behavior, animations. The AI will not add these unless you ask.
  • Tech constraints: "Use Tailwind CSS classes" and "Use Next.js App Router" prevents the AI from writing vanilla CSS or React Router code that won't work in your project.

Before vs After

Bad prompt
"Make a hero for my site"

The AI has to guess everything: colors, layout, content, buttons, animations. You'll get a generic blue gradient hero with placeholder text. You'll spend 30 minutes tweaking it and still hate the result.

Good prompt
The Chapter 4 prompt

The AI has all five ingredients. It returns a production-ready component in your exact brand colors with animations and proper tech stack. You apply it, see it works, and commit. Total time: 3 minutes.

Iteration prompts

Once a section is built, you'll want to tweak it. Iteration prompts are short and surgical. Here are the four patterns you'll use constantly:

make the hero image opacity 60%

The AI finds the Image component in Hero.tsx and changes opacity-40 to opacity-60. Single-line change, instant feedback.

remove the divider in hero

The AI finds the SVG curve divider block in Hero.tsx and deletes it. Surgical removal, nothing else changes.

give the buttons glass effect

The AI changes bg-[#3B82F6] text-white to bg-white/10 border border-white/30 backdrop-blur-md text-white. The AI knows what "glass effect" means in Tailwind.

add 60px more top padding to hero content

The AI changes pt-24 to pt-[calc(6rem+60px)]. Arbitrary value syntax lets you specify exact pixel values that aren't in Tailwind's default scale.

Anti-patterns (what NOT to do)

  • Don't say "make it look nice". "Nice" is subjective. The AI will produce something generic. Always describe specific colors, spacing, and proportions.
  • Don't say "use modern design". "Modern" means different things in 2024 vs 2018 vs different design movements. Specify the look: "minimalist with lots of whitespace" or "editorial magazine layout".
  • Don't dump 10 requests in one prompt. The AI will do them all badly. One prompt = one component or one change. Sequence them.
  • Don't be afraid to give exact code refs. "Match the style of the navbar in PublicNavbar.tsx" is great. The AI reads the file and replicates the pattern.
Remember: The AI is your junior developer. Be specific about what you want, review every change before committing, and never trust the first version. Iterate until it's right.
Chapter 6

Build the navbar with active states

The navbar appears on every page, so it needs to work everywhere. We'll build a navbar that sits transparent over the hero on the homepage, detects which page the user is on, and highlights that link with a blue underline. This is the "active state" pattern that every modern website uses.

Build a public navbar component for the Enginest Next.js App Router site. Links on the right: Resources, Solve Them, AI Assistant, About, plus a "More" dropdown containing Success Stories, Services, Careers, FAQ. Logo on the left. Two CTA buttons on the far right: "Sign In" with glass effect (bg-white/10, border-white/30, backdrop-blur-md), "Get Started" with solid white background and black text. Use usePathname() from next/navigation to detect the active page. Active link gets white text and a full-width blue underline (h-0.5 bg-[#3B82F6]); inactive gets text-white/70 and a hover underline that animates from 0 to full width on hover. The More dropdown parent should also show active styling if any of its children match. Position absolute over the hero with bg-transparent. Include a mobile menu that slides down on small screens.

How usePathname works

Next.js provides a hook called usePathname() that returns the current URL path as a string. If you're on /solve-them/some-problem, it returns "/solve-them/some-problem". We use this to detect which nav link is active. The trick is that we want the "Solve Them" link to be active on both /solve-them AND /solve-them/any-slug, so we use a helper function:

typescript
function isActive(pathname: string, href: string): boolean { if (href === "/") return pathname === "/" return pathname === href || pathname.startsWith(href + "/") }

This returns true if the current path exactly matches the link's href, OR if the current path starts with the href followed by a slash. So /solve-them/anything matches the /solve-them link. The homepage is special-cased because every path starts with /, which would make Home always active without that check.

Chapter 7

Build the Solve Them problem catalog

Solve Them is the heart of Enginest. It's a searchable, filterable catalog of real-world engineering problems sourced from WHO, UN, IEA, and other authoritative organizations. Each problem has a category, difficulty level, impact score, and detailed writeup. This is the page where users spend the most time.

Build a Solve Them page at /solve-them that lists 30+ curated world problems in a card grid. Each card shows: category badge (top-left), difficulty badge with color (Easy=green, Medium=yellow, Hard=orange, Frontier=red), problem title (large), 2-line summary, and a footer row with Impact score, Innovation score, and Severity icons. Add a left sidebar with filters: Category dropdown, Difficulty selector, Scope (Local/Regional/Global), and a "Sort by" dropdown (Impact / Innovation / Newest). Add a search bar at the top that filters by title and summary. Use a light theme that matches the rest of the site: bg-background, bg-card, text-foreground, text-muted-foreground, border. Make cards clickable — clicking navigates to /solve-them/[slug] detail page.

The data structure

Behind every catalog is a dataset. For Enginest, we store problems in a TypeScript file at src/lib/solve-them/problems.ts. Each problem is a typed object with these fields:

typescript
type Problem = { slug: string // URL-safe identifier title: string // "Affordable Clean Water for Coastal Cities" summary: string // 1-2 sentence description category: string // "Water" | "Energy" | "Health" | ... difficultyLevel: "EASY" | "MEDIUM" | "HARD" | "EXTREME" difficulty: number // 1-10 impactScore: number // 1-100 innovationScore: number // 1-100 severity: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL" scope: "LOCAL" | "REGIONAL" | "GLOBAL" estimatedTimelineMonths: number peopleAffected: string // "1.2B" skillsRequired: string[] // ["Materials Science", "Mechanical Engineering"] // ... plus detailed content for the detail page }

TypeScript types are powerful because they prevent bugs. If you try to set difficultyLevel: "EXTREME" on a problem, the type system accepts it. If you try difficultyLevel: "INSANE", you get a red squiggle in VS Code instantly. This is why we picked TypeScript in Chapter 2.

Chapter 8

Build the AI Innovation Engine

This is the signature feature of Enginest: a tool that asks users for their skills and interests, then matches them to problems they're uniquely positioned to solve. The matching algorithm is straightforward but feels like magic to the user. This page lives at /dashboard/innovation-engine and requires authentication.

Build an Innovation Engine dashboard page at /dashboard/innovation-engine. Two-column layout: Left column (1/3 width) has three input cards: (1) "Your Skills" — chip input where users add skills like Python, ML, React. Show common skill chips below as quick-add buttons. (2) "Your Interests" — same chip input pattern for AI, Climate, Healthcare, etc. (3) "Constraints" — three controls: time commitment slider (1-60 months), team size slider (1-30 engineers), difficulty dropdown (Any/Easy/Medium/Hard/Frontier). A big blue "Generate Innovations" button at the bottom of the left column. Right column (2/3 width) shows matching problems sorted by match score (0-100). Each match card shows the score number prominently, problem title, 2-3 reason highlights ("You have Python which is required", "Your interest in Climate matches"), matched skill chips, and metric icons. Use a matchInnovations() helper that scores each problem based on skill overlap, interest overlap, time fit, and difficulty fit.

How the matching algorithm works

The matchInnovations() function takes the user's input (skills, interests, constraints) and returns a sorted array of problems with match scores 0-100. The score is calculated as a weighted sum:

  • Skill overlap (40%): How many of the problem's required skills match the user's skills. If a problem needs Python and ML, and the user has both, full marks.
  • Interest overlap (30%): Does the problem's category align with the user's stated interests? Climate interest + Water problem = high alignment.
  • Time fit (15%): Does the problem's estimated timeline fit within the user's stated time commitment? If the problem needs 24 months but the user has 6, partial credit.
  • Difficulty fit (15%): Does the problem's difficulty match the user's preference? If the user picked "Easy" but the problem is "EXTREME", low score.

The function returns problems sorted by score descending, with the top 10 shown by default. Users can adjust their inputs and re-generate to see different matches. This is the entire "AI" of the Innovation Engine. No external API calls, no machine learning models. Just a deterministic scoring function. The magic is in the UX, not the algorithm.

Chapter 11

Deploy to Vercel

Time to put your site on the internet. Vercel makes this painfully easy, the entire process takes about 3 minutes. Once deployed, every git push to your main branch triggers an automatic rebuild and redeploy. You'll never manually deploy again.

1
Sign up at Vercel

Go to vercel.com and sign up using your GitHub account. This links your GitHub to Vercel so deploys happen automatically. The free Hobby tier is more than enough for personal projects.

2
Import your repository

Click "Add New..." → "Project". Vercel shows a list of your GitHub repos. Find enginest and click "Import". If you don't see it, click "Adjust GitHub App Permissions" and grant Vercel access to that repo.

3
Configure and deploy

Vercel auto-detects Next.js and fills in all the build settings correctly. You usually don't need to change anything. Scroll down and click "Deploy". The first build takes about 90 seconds.

4
Visit your live site

Once the build finishes, Vercel shows you a success page with confetti. Click "Visit" to see your site live at a URL like enginest-abc123.vercel.app. Share this URL with anyone in the world, they can see your site.

5
Set environment variables

If your site uses a database, authentication, or any external service, you'll need to add environment variables. In your Vercel dashboard, go to Settings → Environment Variables. Add keys like DATABASE_URL, NEXTAUTH_SECRET, NEXTAUTH_URL. Vercel stores these encrypted and injects them at build time. Redeploy after adding them.

6
Custom domain (optional)

Buy a domain from Namecheap, Cloudflare, or Google Domains. In Vercel, go to Settings → Domains, add your domain, and follow the DNS instructions. Vercel handles SSL certificates automatically. Within 24 hours, your site is live at your custom domain.

The auto-deploy loop

Here's the magic: from now on, every git push to your main branch triggers Vercel to rebuild and redeploy automatically. You make a change locally, push, and 90 seconds later it's live. Vercel also builds preview deployments for every branch and pull request, so you can test changes before they hit production. This is the modern web development workflow.

Chapter 12

Common pitfalls and fixes

Real projects hit real problems. Here are five actual issues from the Enginest build, with the symptoms and fixes. When you hit similar issues, refer back here.

Problem 01
Invisible text on Innovation Engine dashboard page

The dashboard page was originally built with a dark navy theme (bg-[#0F1B3D], text-white), but it was being rendered inside the light-theme DashboardLayout (bg-background, text-foreground). Result: white text on white background. User reported "the text and bg color are same, I can't see, not visible".

Fix

Rewrote the page to use light-theme tokens: bg-background, bg-card, text-foreground, text-muted-foreground. These tokens come from the DashboardLayout's color scheme and automatically work in both light and dark modes. Lesson: always use design tokens, never hardcode colors that depend on a specific theme context.

Problem 02
Hero image too dark, can't see the picture

Initial setup had the hero image at opacity-40 with a dark navy gradient overlay at 85-95% opacity on top. The combined effect made the image almost invisible. User said "remove the opacity" and "make it 60%".

Fix

Bumped image opacity from 40% to 60% and lowered the overlay opacity from 85-95% to 55-65%. The image now reads clearly while text contrast is preserved. Lesson: when stacking image + overlay, the visible image opacity is roughly image_opacity × (1 − overlay_opacity). 0.6 × 0.35 = 21% effective visibility, which is the sweet spot for hero backgrounds.

Problem 03
Em-dashes (—) everywhere in the copy

The AI had used em-dashes liberally throughout the site's marketing copy: "Find problems — worth solving — with AI". This looked unprofessional and inconsistent. A scan found 455 em-dashes across 45 source files.

Fix

Wrote a Python script that walked the src/ directory, replaced every em-dash (U+2014) with a comma, and skipped files where the em-dash was inside a regex literal (like .replace(/—/g, ",")). Saved the script to scripts/remove-em-dashes.py so it can be re-run on new content. Lesson: batch fixes deserve scripts, not manual edits.

Problem 04
Logo looked too small in the navbar

Initial logo size was h-9 (36px). On a 1920x1080 screen, this looked tiny next to the navigation links. User reported "make the png logo width and height big, it's small now".

Fix

Bumped navbar logo to h-12 (48px), footer logo to h-16 (64px), and dashboard sidebar logo to h-11 (44px). The key insight: use h-XX w-auto so the logo preserves its aspect ratio. Never set both width and height independently, that stretches the image. Lesson: pick a height and let the width auto-scale.

Problem 05
Brand name appeared twice — in logo image AND as text next to it

The Photoroom-processed logo PNG already contained the word "Enginest" baked into the image. But the navbar code also rendered <span>Enginest</span> next to it. Result: "Enginest Enginest" in the navbar.

Fix

Removed the <span>Enginest</span> from PublicNavbar, Navbar, Footer, PublicFooter, DashboardLayout, and all four auth pages. The logo PNG now carries the brand name visually. Lesson: when your logo image contains text, don't duplicate it as HTML text. This also helps screen readers — the alt="Enginest logo" on the Image handles accessibility.
